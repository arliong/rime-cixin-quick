# 踩坑與解法手冊（librime-lua 輸入法組件開發）

> 按 主題分類 的排雷清單。每條坑都真實踩過，附驗證方法。
> 適用環境：Weasel 0.17.4 / librime 1.13.1 / librime-lua / Lua 5.4。

## 1. 模塊加載

| 坑 | 真相 | 解法 |
|----|------|------|
| `func type: nil` | Lua 模塊放 `%APPDATA%\Rime\` 根目錄 require 找不到 | 必須放 **`lua\` 子目錄** |
| require 失敗的連鎖誤導 | 「attempt to call a nil value」「utf8 缺失」都可能是 require 失敗的下游症狀 | 先看部署日誌的 module not found 段落確認搜索路徑 |
| schema 寫法 | `lua_processor@ms_quick_predict` 依賴 rime.lua 全局註冊，容易斷 | 用 `lua_processor@*模塊名`（`*` 前綴自載入） |

**驗證法**：部署後 grep 日誌 `loaded`；更狠的一招是對 rime.dll 做二進制
grep 確認 API 是否存在（本例實錘 723 個 Lua C API 導出）。

## 2. 按鍵處理（KeyEvent）

| 坑 | 真相 | 解法 |
|----|------|------|
| Shift+1 出 `!` | 鍵碼是**翻譯後的 keysym**：Shift+1 → `!`（0x21），不是 `1`（0x31） | DIGIT_MAP 雙形態：`0x21..0x29` 與 `0x31..0x39` 都映射到 1..9 |
| 每鍵觸發兩次 | keyup（釋放事件）也進 processor 鏈（Weasel 要用它判 Shift 中英切換） | `key:release()` 為真直接放行；再加 150ms 同鍵去重兜底 |
| 純 Shift 動了標記 | 只按 Shift 也會觸發 key 事件 | `0xFFE1/0xFFE2` 放行不處理，否則候選欄閃爍 |
| 聯想態數字被 selector 搶 | 候選欄存在時數字鍵被選字搶走 | 聯想標記態的按鍵語義全部自定義：數字=接龍、Esc=取消、字母/空格/標點=清標記放行 |

## 3. librime API 形態（最大坑區）

| 坑 | 真相 | 解法 |
|----|------|------|
| `ctx:set_input("~")` 拋錯 | librime-lua 的 Context **沒有 set_input 方法**，`input` 是屬性 setter | 讀值 `ctx.input`；置值 `ctx.input = "x"`；有 `push_input` / `clear` 方法 |
| 設了 input 又消失 | `Context::Commit()` 是**先 commit_notifier 後 Clear()**（1.13.1 源碼實錘） | commit_notifier 只置標誌，在 **update_notifier**（Clear 之後觸發）裡再 `push_input` |
| update_notifier 被覆蓋？ | 不會：槽序 Engine 先、Lua 後；Engine 對空 input 的 Compose 先跑完 | 直接在回調裡 push，觸發嵌套 Compose |
| 盲接鏈路與 notifier 打架？ | 不會：`engine:commit_text()` **不觸發** commit_notifier | 兩條鏈路天然隔離 |
| 錨定文字取舊值 | commit_notifier 回調時 `commit_history:latest_text()` 尚未更新 | 用 `ctx:get_commit_text()`（回調時實時正確），latest_text 作兜底 |
| `type(x)=="table"` 判錯 | librime-lua 對像是 userdata | 真值判斷 + pcall 包裹一切跨邊界調用 |
| Lua 5.4 宏陷阱 | `lua_pcall` → `lua_pcallk`、`lua_pop` → `lua_settop` | ctypes 綁定時按 5.4 實際導出名 |

## 4. 候選欄與翻譯器

| 坑 | 真相 | 解法 |
|----|------|------|
| 上屏後 translator 不被查詢 | 上屏瞬間組字被 Clear，composition 為空 | 合成分段：update_notifier 裡 `push_input("~")`，`~` 不在 alphabet，由 punct_segmentor 接手，lua_translator 對 `input=="~"` 生成候選 |
| 空候選欄殘留 `~` | 該字沒有聯想詞也推了標記 | 推標記前先查索引有無聯想詞 |
| 標點候選搶首位 | punct_translator 也對 `~` 出候選 | 聯想 translator 放 translators 列表**首位** |
| 「XP 式雙行候選」做不了 | RIME 候選窗只渲染單一激活分段菜單；上屏瞬間原組字已 Clear | 無對應機制，放棄（硬做 = 重寫 table_translator，不值） |

## 5. 反查（reverse_lookup_translator）

| 坑 | 真相 | 解法 |
|----|------|------|
| 反查靜默無候選 | 加載正查詞典需 **table+prism+reverse 三件套**，缺 prism 即 `loaded=false` 且**無任何錯誤提示**（只有部署日誌一行 error） | grep 部署日誌 `prism`；確保目標詞典所屬方案進過 schema_list |
| prism 從未生成 | prism 隨**方案部署**才編譯；作為他方案反查依賴只編 table/reverse | schema_list 加入對應方案（如 luna_pinyin），或手動無頭部署 |
| 想掛第二個反查 | 查 `reverse_lookup_translator.cc` 實錘：支持 `@實例名` 多實例 + 自定義 `tag` | `reverse_lookup_translator@stroke_lookup` + `stroke_lookup:` 配置塊 + recognizer pattern 綁定 |

## 6. 部署與測試

| 坑 | 真相 | 解法 |
|----|------|------|
| 部署後行為沒變 | 舊 WeaselServer 進程還在報舊錯，日誌裡多個 PID 混雜 | 以日誌時間戳分辨；必要時徹底重啟服務 |
| WeaselDeployer `/deploy` 靜默退出 | 命令行觸發有時加載完配置就退（原因未明） | **無頭部署法**：停服務 → ctypes 調 rime.dll 維護接口
  （`rime_get_api` + `start_maintenance(full_check)` + join thread）→ 驗證 build 產物 → 重啟服務 |
| 本機沒有 lua.exe | 不需要！rime.dll 內嵌完整 Lua 5.4 | ctypes 驅動 `luaL_loadbufferx` 做語法校驗；驅動真實 C API 做 mock 測試 |
| mock 測試連發撞去重 | 150ms 去重會把連續用例擋掉 | 用例間換首字，或測試態關去重 |
| 部署日誌在哪 | `$env:LOCALAPPDATA\Temp\rime.weasel\*.log.INFO.*` | `Get-Content ... -Tail 30 | Select-String "組件名"` |

## 7. 方法論

1. **讀源碼十分鐘，勝過盲試兩小時**：所有 API 形態問題（set_input、
   Commit 時序、多實例反查）最終都靠讀 librime / librime-lua 源碼實錘。
2. **二進制 grep 驗 API**：懷疑「函數到底存不存在」時，對 rime.dll
   grep 導出表最快。
3. **真實環境 mock**：用 rime.dll 內嵌 Lua 驅動真實 C API 寫測試，
   比純字符串 mock 可靠得多（第 11 輪 20 用例全綠 = 後續重構底氣）。
4. **一切以 build 產物時間戳為準**，「我部署過了」不算數。
