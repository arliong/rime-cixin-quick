# 開發歷程：兩天 14 輪，從「什!」到完整聯想

> 記錄 2026-09-26 深夜至 09-28 凌晨的完整開發過程。每輪都是
> 「症狀 → 排查 → 修復」的真實軌跡，供後來者參考與避坑。

## 背景

目標：在 RIME/小狼毫（Weasel 0.17.4 / librime 1.13.1）的「傳統速成」
方案中，完整復刻 Windows XP 傳統速成的詞組聯想——打 `oj` 選 1 上屏
「什」後按 Shift+1..9 接龍出「麼/邡/錦/麼的…」。

項目初期多輪嘗試集中在 Lua 組件加載問題上，均未成功。

## 第 7 輪：模塊加載真因 + 測試基建

- **症狀**：`func type: nil`，Lua 組件反覆加載失敗。
- **排查**：對 rime.dll 做二進制 grep，實錘導出完整 Lua C API（723 個
  導出）→ 用 ctypes 驅動 rime.dll 內嵌的 Lua 5.4 做真實 mock 測試；
- **真因**：Lua 模塊必須放在 `%APPDATA%\Rime\lua\` 子目錄，放根目錄
  require 必失敗；schema 裡用 `lua_processor@*模塊名` 的 `*` 前綴
  自載入形式（不依賴 rime.lua 全局註冊）。
- **同輪**：預建索引方案確定（首字 → 詞組列表，詞頻序，707KB），
  運行時零遍歷。

## 第 8 輪：Shift+1 的鍵碼陷阱

- **症狀**：打 `oj` 上屏「什」後按 Shift+1，候選欄出現 `什!`。
- **真因**：KeyEvent 的鍵碼是**翻譯後的 keysym**——Shift+1 到達時是
  `!`（0x21），不是數字 `1`（0x31）。
- **修復**：DIGIT_MAP 雙形態映射（移位符號形 + 直數字形）。

## 第 9 輪：雙字 bug

- **症狀**：接龍出「什麼麼」，同一字出兩次。
- **排查**：日誌實錘 keyup（釋放事件）也在 75-106ms 後進了處理器鏈
  並被接龍一次（Weasel 需要 keyup 判斷 Shift 切中英）。
- **修復**：keyup 過濾（`key:release()`）+ 150ms 同鍵去重。

## 第 10 輪：盲接鏈路通 ✓

實測：`什麼邡錦麼的麼是麼樣麼都麼呢麼人` 九鍵全對，無雙字。
**v1.0 功能完成。**

## 第 11 輪：打包 + 候選欄聯想（第一版嘗試）

- 打包為「慈心速成」供 Rime package installer 安裝；
- 候選欄可見聯想第一版：commit_notifier 回調裡 `set_input("~")`
  合成標記分段 → lua_translator 對 `~` 生成聯想候選。mock 20/20 通過。

## 第 12 輪：候選欄 ok=false，雙坑疊加

- **症狀**：日誌 `mark set after [什] ok=false`，候選欄不出現；
  盲接鏈路（另一條路徑）完全正常。
- **排查**：逐行讀 librime 1.13.1 `context.cc` 與 librime-lua `types.cc` 源碼：
  1. **坑一**：librime-lua 的 Context **沒有 `set_input` 方法**，
     `input` 是屬性 setter（`ctx.input = "x"`）→ 調 nil 方法拋錯被 pcall 吞掉；
  2. **坑二**：`Context::Commit()` 是**先觸發 commit_notifier、後執行
     Clear()** → 就算設對了，回調裡設的 input 也會被緊隨其後的
     Clear 清掉。
- **修復**：commit_notifier 只置 `pending_mark` 標誌；新增
  **update_notifier** 回調（Clear 之後觸發，槽序 Engine 先、Lua 後，
  嵌套 Compose 不被覆蓋）裡 `ctx:push_input("~")`；Esc/清標記改用
  真實存在的 `ctx:clear()`。
- **附帶實錘**：`engine:commit_text()`（盲接鏈路）不觸發
  commit_notifier → 兩條鏈路互不干擾。

## 第 13 輪：雙通道反查

- 候選欄 OK；XP 的「原候選保留 + 下方橫向聯想行」評估後
  確認 RIME 引擎無對應機制（候選窗只渲染單一激活分段菜單，且上屏
  瞬間原組字已被 Clear）——不做，保持現狀。
- **新增**：拼音反查（原有 ` + 拼音，補 enable_completion）＋
  筆畫反查（`'` + hspnz，掛小狼毫自帶 stroke 词典）。查
  `reverse_lookup_translator.cc` 實錘支持 `@實例名` 多實例與自定義
  `tag`，注釋自動反查主碼表顯示速成碼。

## 第 14 輪：拼音反查靜默失效

- **症狀**：筆畫反查通，拼音反查按 `` ` `` 無任何反應。
- **真因**：部署日誌 `error opening prism file 'luna_pinyin.prism.bin'`
  ——方案列表從不含 luna_pinyin，prism（音節索引）從未編譯；反查
  翻譯器加載正查詞典需 table+prism+reverse 三件套，缺一即**靜默**
  返回空。
- **修復**：schema_list 加 luna_pinyin。部署一波三折（WeaselDeployer
  命令行兩次無聲退出），改用 ctypes 直調 rime.dll 維護接口完成
  無頭部署（`tools/_rime_maintenance.py`，隨倉庫提供），編譯驗證通過後重啟服務。

## 收尾

在另一台機器實測一切正常——第 14 輪的「異常」實為本機安裝環境
問題。項目轉入整理與開源發佈階段（本倉庫文檔）。

## 經驗密度最高的三條

1. **讀源碼，別猜 API**：第 12 輪兩個坑都是讀 librime/librime-lua 源碼
   十分鐘實錘的；此前若先讀源碼可省一輪。
2. **日誌麵包屑是好習慣**：每輪排查都靠 `log.info` 麵包屑定位到
   具體失敗點（ok=false 是誰、keyup 為何重入）。
3. **別信「部署了」**：Weasel 的部署有時序問題（舊進程報舊錯、
   部署器靜默退出），一切以 build 產物時間戳 + 編譯日誌為準。
